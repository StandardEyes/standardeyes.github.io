How it works

What StandardEyes does with your data

A plain account of each step: what is computed, which test is used when, and what the output means. The statistical reference gives the full detail.

Lay out your data

StandardEyes reads an Excel sheet (.xlsx or .xlsm) with one row per eye per surgery. Column names are yours to choose. You tell the app what each column is, and it never guesses from a name.

You point the app toIt is used for
Patient IDLinking the two eyes of one person. The patient is the cluster in every clustered model and the unit for patient-level variables.
Eye IDIdentifying the row.
Group source columnThe column whose values define the groups you compare.
Refraction and acuity columnsPreoperative and postoperative sphere, cylinder, axis, spherical equivalent (SEQ), uncorrected and corrected distance visual acuity (UDVA, CDVA). They feed the figures and the export tabs.
  • A retreatment is another row for the same eye. A rule such as “surgery number = 1” restricts the analysis to primary procedures.
  • A row without a patient ID is counted as its own patient, and the run log says how many such rows there were. With no patient ID column at all, eyes are treated as independent and the output says so.
  • A cell formatted as a date inside a column of numbers is treated as missing and reported, because Excel's hidden date number would otherwise distort the results.

Groups and the reference group

A group is a set of values of the group source column. You can define two groups or more. One group is the reference: every effect estimate, every matching pairing and every adjusted model is expressed relative to it. It is usually the control group or the standard technique.

Variables that describe the person and not the eye (age, sex, a systemic disease) can be marked per patient. They are then summarized once per patient, and the table headers show both counts, for example Control (n = 108 eyes; 73 patients).

Variable types and tests

Each variable you analyse is given one of four types. The type decides how it is summarized and which test compares the groups.

TypeReported asTwo groupsThree or more groups
Continuousmean ± SDWelch t-testWelch ANOVA
Ordinalmedian [IQR]Wilcoxon rank-sumKruskal–Wallis
Dichotomousn (%)χ² test, or Fisher's exact test
Categoricaln (%) per levelχ² test, or Fisher's exact test
  • Welch tests are used because they do not assume that the groups have equal variances. Groups of different size and spread seldom do.
  • The χ² test is used when every expected count is at least 5. Otherwise Fisher's exact test is used.
  • The summary sheets write the test that was used beside every P value. The publication-style table leaves the test column out, so take the test names from the summary sheets for your methods section.
  • These tests work on eyes. When patients contribute two eyes, add the clustered models.
  • When a test cannot be done (a group with a single value, a variable that has the same value in every eye), the row says “Not estimable” and gives the reason. It is never reported as “no difference”.
  • P values in the summary tables are not adjusted for multiple comparisons.

Plus and minus cylinder

Files often mix plus- and minus-cylinder notation. When the option is on, every sphere / cylinder / axis set you list is transposed to minus cylinder: new sphere = sphere + cylinder, new cylinder = −cylinder, new axis = axis ± 90°. A cylinder value above zero is taken as plus notation, so no notation column is needed. Rows already in minus cylinder are left alone. All later steps, including the astigmatism vectors, then work on one notation.

Visual acuity notations

One setting, VA notation in your file on the Variables & Types tab, says how every acuity column is recorded.

NotationExamplesHow it is read

  • The tables, tests and models can run in logMAR (optional). A file already in logMAR is never converted twice.
  • The figures and the mEYEstro tab always work from decimal acuity derived from your notation, so they are the same whichever notation the file uses.
  • Counting fingers, hand motion and light perception (CF, HM, LP, NLP) become missing values and are counted in the log. They are not given an invented acuity.
  • If the values clearly cannot be in the notation you chose (most cells unreadable, a decimal value of 0 or below, a logMAR value outside −0.5 to 3, or decimal values declared as ETDRS letters), the run stops and names the column. Subtler mismatches, such as decimal values declared as logMAR, give a warning in the interface and in the log, so read the warnings.
  • Inclusion rules on acuity use the values in your file's own notation.
  • Excel turns a typed 6/12 into a date. Format Snellen columns as text.

Inclusion rules and subsets

Inclusion criteria are rules on columns, combined with AND: equal to, in a list, greater or less than, between, missing or not missing, text contains, and absolute-value versions for cylinder (so “absolute value ≤ 5” keeps −5.00 D and +5.00 D alike). Rules see refraction after the plus-to-minus transposition, and acuity in your file's own notation. As you add a rule, the app shows how many rows remain and how many each group lost.

A subset column (for example the procedure) splits one preset into a complete, separate analysis for each value: a full PRK analysis and a full LASIK analysis, each with its own workbook and figures.

Matching

Matching makes the groups comparable on the baseline variables you choose. The propensity score is each eye's estimated chance of being in the compared group, given those variables. Eyes with similar scores are paired. StandardEyes uses the R package MatchIt and matches each group to the reference group. The default is 1:1 nearest-neighbour matching on the propensity score, without replacement, with a caliper (the largest allowed difference) of 0.2 standard deviations of the propensity score. Exact matching, coarsened exact matching and subclassification are also available.

  • A live preview (for nearest-neighbour matching) runs the real matching on your current settings and shows, for each pairing, how many eyes had complete covariates and how many were matched.
  • Balance is reported as standardized mean differences before and after matching, against the usual 0.1 threshold. A love plot shows the difference for each covariate before and after matching.
  • When the matching weights are not all 1 (matching with replacement, k:1 matching in which some eyes find fewer than k controls, or exact, coarsened exact or subclassification matching), the matched tables, models and figure P values use the weights, and the headers show the effective sample size.

Matching deals with measured confounders only. It does not turn an observational comparison into a randomized one.

Two eyes per patient

Two eyes of one person are more alike than two eyes of different people. A test that treats them as independent gives P values that are too small. StandardEyes offers generalized estimating equations (GEE), a regression method that takes the patient as a cluster and uses robust standard errors (R package geepack). The working correlation is exchangeable. On a matched group whose matching weights are not all 1, the model is weighted and uses an independence working correlation, the estimator that MatchIt recommends.

  • Continuous outcomes give a mean difference. Dichotomous outcomes give an odds ratio. Both come with a 95% confidence interval.
  • The GEE effect and P value can be added as columns to the summary tables.
  • The P values printed on the figures are clustered by patient by default.
  • A clustered model needs at least 6 usable eyes from at least 3 patients, and every compared group needs 2 eyes from 2 patients. Otherwise the row says it is not estimable and why. A group with 2 to 9 patients gets a P value with a caution, because robust standard errors can be too small with few patients.

If every patient contributes one eye, the ordinary tests are appropriate and GEE adds nothing.

Adjusted regression

For each outcome the app can fit a model of the outcome on the group and the covariates you choose, again clustered on the patient. The adjusted effect, its 95% confidence interval and P value are written next to the crude comparison in the outcome table, and the full models go to their own sheet.

  • The app suggests covariates by baseline imbalance (standardized mean difference above 0.10), plus age and sex. Choose covariates for imbalance, not for their effect on the P value.
  • A covariate that is constant after the inclusion rules is dropped, with a note.
  • When one group has no events (or only events), the odds ratio does not exist. The comparison is reported as not estimable, with the reason.

Matching and adjustment can be combined in one run: match on the measured confounders, then adjust for what is still imbalanced.

The figures

The figures follow the standard graphs for reporting refractive-surgery outcomes (Dupps et al., J Cataract Refract Surg 2011;37:1–3. Reinstein et al., J Cataract Refract Surg 2017;43:435–439), with one difference: every group is drawn on the same chart, in its own colour.

Panel setContains
FullVisual acuity, efficacy, safety, spherical-equivalent accuracy, attempted versus achieved, defocus equivalent, refractive astigmatism, the vector panels, and stability over time when visits are mapped.
RefractiveThe Full set without defocus equivalent, stability and the vector panels.
CataractThe Refractive set without safety and attempted versus achieved. Efficacy is measured against postoperative CDVA.
  • With two groups each panel prints one test and names it. With three or more it prints an overall test and each group against the reference. Those comparisons are corrected for multiple testing by the Holm method and marked [Holm].
  • Stability over time plots mean ± SD spherical equivalent at each mapped visit, at the median day actually observed, with the number of eyes under each point. Nothing is carried forward.
  • An optional target column holds the intended spherical equivalent of each eye (monovision, a myopic target). Without it, eyes are taken as aimed at plano.
  • Each panel is written as its own file and inside the combined figure, as TIFF (300 dpi by default), PNG, JPEG or PDF.

Astigmatism

Astigmatism is analysed as vectors by the Alpins method: target induced astigmatism (TIA), surgically induced astigmatism (SIA), the difference vector and the correction index. The vectors are computed from the preoperative and postoperative cylinder and axis you map, or read from your own columns.

The plots follow the JCRS standards for astigmatism analysis (Koch et al., J Cataract Refract Surg 2025;51:447–455):

  • Double-angle plots, with each group's centroid (its mean vector), the 95% confidence region of the centroid, and a 95% region of the eyes drawn as a convex polygon. An ellipse is available for normally distributed data.
  • For each group: the centroid, the total standard deviation, the mean and median vector magnitude, and the share of eyes within 0.25, 0.50, 0.75 and 1.00 D.
  • Centroids are compared with one two-dimensional test, not two separate tests on x and y. The default is a robust test on trimmed means with a bootstrap that resamples patients. A clustered GEE test and the classical Hotelling test are also offered.
  • Every figure prints the method that produced its numbers.

Reproducibility

  • A preset stores every setting of a study in one small JSON file. Loading it restores the analysis exactly, on your computer or a colleague's.
  • The Manifest sheet of every workbook records the StandardEyes version and build (for runs started from the app), the R and package versions, the input file and its checksum, the number of inclusion rules, the acuity, matching, GEE and regression settings, and the random seeds. The preset holds every setting, so keep it with the workbook.
  • Steps that use random numbers (matching order, the bootstrap, Monte-Carlo exact tests) use fixed seeds, so the same input gives the same output.
  • All numbers are computed by the R engine, which also runs from the command line with the same settings file.

Known limits

  • The ready-to-run download is for Windows and needs R 4.5. Other systems can run from source.
  • On a matched group with weights that are not all 1, there is no weighted test for a categorical variable with more than two levels, nor for a proportion when one group has no events. Those cells say so.
  • The robust astigmatism centroid test has no weighted form. On such a matched group the figure states that it does not use the weights.
  • Confidence intervals of the clustered models are Wald intervals without small-sample correction, hence the caution for groups with few patients.
  • PDF figures cannot render right-to-left text (Hebrew, Arabic) in group labels. Use PNG or TIFF for those.
  • One analysis runs at a time.

Frequently asked questions

Does my data leave my computer?

No. The app runs on your computer and listens only on the local address 127.0.0.1. It has no telemetry and makes no network requests.

Is it free? May I use it for a commercial study?

Yes to both. It is released under the MIT License.

Do I need to know R?

No. R must be installed, but you never open it. Everything is done in the app's interface.

Does it run on a Mac?

The ready-to-run download is for Windows 10 and 11. On macOS or Linux the app runs from source with Python and R 4.5. The README lists the steps.

My data is in CSV or an old .xls file. Can I use it?

Open it in Excel and save it as .xlsx. The app reads .xlsx and .xlsm files.

My acuity is in Snellen or logMAR. Do I have to convert it?

No. Choose the notation on the Variables & Types tab and the app reads it as it is. See visual acuity notations.

Can I use it for one group only?

StandardEyes is built for comparisons and needs at least two groups. For a single group, the tools mEYEstro and AstigMATIC are a good fit.

Can I use it for cataract or lens surgery?

Yes. The Cataract panel set measures efficacy against postoperative CDVA, and the optional target column handles eyes that were not aimed at plano.

Is anything saved before I choose to save?

With Preview only ticked, no. Results are held inside the app so you can look at them, and nothing is written to your output folder until you save. Without it, the run saves straight to the output folder.

Why does a table show one P value and the figure another?

The table P value comes from the eye-level test named beside it. The figure, by default, prints the P value clustered by patient. Switch on the GEE columns (source: main model) to show the clustered P value in the table as well. With two groups it then equals the figure's P value, provided a patient ID is mapped and, on a matched group with unequal weights, Use matching weights is on. With three or more groups the figure prints an overall test, while the GEE columns compare each group with the reference.

Are the P values corrected for multiple comparisons?

Only the group-against-reference lines on the figures, by the Holm method. The P values in the tables, the GEE sheets and the regression sheets are not adjusted. Name a primary outcome in advance, and read borderline P values with the number of tests in mind.

How do I share a study with a colleague?

Save the study as a preset and send the .json file from webapp\presets, or use Download config JSON. The preset holds the settings only, not the data. Your colleague loads the same spreadsheet and the preset, and gets the same analysis.

How should I describe the analysis in my methods section?

Name the tests shown in the Test column of your summary sheets, describe the matching and GEE settings listed in the Manifest sheet, give the StandardEyes version, and cite the software. The statistical reference has wording you can adapt.

I found a problem. Where do I report it?

Open an issue on GitHub or write to dror.ben.ephraim@gmail.com. Please include the version and the run log, and never send patient data.
