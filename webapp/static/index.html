Visual acuity

Applies to every column mapped to a VA role (Pre/Post UCVA and BCVA, Special outputs tab) and to the logMAR columns below. Snellen may be written 20/x or 6/x, with letter suffixes such as 20/25-2. Off-chart entries (CF, HM, LP, NLP) become missing and are counted in the run log; they are never given an invented acuity. The run stops if most of a column cannot be read in the chosen notation, and when a column declared as ETDRS letters looks like decimal acuity (more than half of its numbers are not whole numbers, or its largest value is below 5). Excel turns a typed 6/12 into a date, so keep Snellen columns formatted as text.

logMAR = −log10(decimal VA); summaries, tests and GEE run on the logMAR values (lower = better vision, 0 = 20/20). An acuity cell then reads the Snellen geometric mean with the logMAR mean ± SD, e.g. “20/20 (0.00 ± 0.05 logMAR)”, and the range in Snellen. Untick to analyze acuity as recorded (the v1.0.0 default). Filter rules and exclusions always use the values as recorded in your file, so a filter typed in your own units means what it says.

The list follows the columns mapped to the four VA roles (Pre/Post UCVA and BCVA, Special outputs tab) until you edit it.

The figures and the mEYEstro / Alpins export tabs always read acuity as decimal (converted from the notation above) — you can convert any column freely; only the statistical analysis switches to logMAR.

Variable roles & statistical types

Propensity-score matching

With >2 groups, each non-reference group is matched to the reference group separately (reference-group pairwise).

Caliper scale: with the logit of the propensity score (default) the caliper is in SDs of the logit of the score (Austin 2011); with probability scale it is in SDs of the score itself (the v1.0.0 default). The PSM sheet, the Manifest and the balance plot name the scale used.

With Standardized on, the caliper is in SDs of the score on the scale of the chosen distance — by default the logit of the propensity score, where 0.2 SD is the usual choice (Austin 2011); with the probability scale (the v1.0.0 default) it is in SDs of the score itself. A mahalanobis distance is not a propensity score: it takes no caliper and no largest / smallest match order (both are adjusted when you pick it), and subclassification cannot use it. A ratio above 1 or Replacement on give the matched controls unequal weights: the matched tables, figure P values and GEE then use those weights, and the workbook notes it above the matched tables. The random seed is fixed, so the same settings give the same matched cohort every run (and in the preview below). The four methods offered here run with the R packages bundled with the app; the live matched-count preview covers nearest only.

Multivariable regression (adjusted analysis)

For studies where matching isn't feasible (very small groups, no good matches) or to adjust residual differences after matching. One model per outcome: outcome ~ Group + covariates, fitted as clustered GEE (eyes nested in patients) — continuous outcomes give adjusted β, complications give adjusted OR; categorical covariates are handled automatically. With more than 2 groups, each group is compared to the reference. Results go to a publish-ready "Regression (adjusted)" sheet plus a full-model appendix, with bold small-sample warnings when a model is asked to do too much.

Outcomes analyzed = the variables in your Outcome section (Variables & Types). Rule of thumb enforced with warnings: ≥10 events per covariate for complications, ≥10 eyes per covariate for continuous outcomes — with few events, keep this list to 2–3 covariates.

Clustered GEE (eye-level, cluster = patient)

GEE gives correct p-values when both eyes of a patient are analyzed: it accounts for the correlation between fellow eyes. Continuous outcomes → linear GEE (β); dichotomous outcomes → logistic GEE (OR).

Which cohort the models are fitted on. matched (usual choice) = after PSM; unmatched = the full filtered cohort; both = both sets of sheets; none = skip GEE.

Which model's effect & p go into the added columns of the summary tables (unmatched and matched, for each cohort GEE is run on).

Every GEE P value and interval (GEE and regression sheets, clustered table tests, figure P values): md corrects the robust SE for few patients (Mancl & DeRouen 2001) and uses a t reference (df = patients − model coefficients; F for joint tests); none repeats v1.0.0.

auto: with a patient-ID column mapped, clustering on and a patient with two analyzed eyes, each per-eye row's P is a patient-clustered GEE test (the same P its figure prints); otherwise, and with classical (v1.0.0), the t-test / Welch, Wilcoxon / Kruskal-Wallis and χ² / Fisher tests run. Turning off Cluster p-values by patient (Special outputs) also gives classical tables. The test name is printed beside each P.

How every P value is printed in the tables, sheets, figures and log: ama gives two decimals (three below .01 or near .05), no leading zero; classic repeats v1.0.0 (three decimals in the tables, four on the figures).

Group effect only. Use after matching, where covariates are already balanced — this is the primary comparison.

Adds the covariates below to the model. Use on unmatched data, or as a sensitivity analysis when residual imbalance remains after matching.

Recommended whenever matching uses replacement or ratio > 1, so each control counts according to how often it was matched. A weighted model uses an independence working correlation with robust standard errors clustered on the patient (the estimator MatchIt recommends), so its effect reproduces the weighted means and proportions printed in the same row. Every model of a matched cohort uses the independence working correlation, weighted or not (matched sets are not used as clusters); unmatched models use the exchangeable one. Figure P values on a matched cohort always use matching weights that are not all 1, whatever this switch says — with it off, the matched GEE columns and the figures can show different p-values.

Copies the group effect (β or OR with 95% CI, and p) into the Baseline / Preop / Outcome tables of every cohort GEE is run on (see Run GEE on), so one table holds everything. The P column of a summary table is patient-clustered (GEE) when a patient has two analyzed eyes and Summary-table tests is auto (the default), and an eye-level test otherwise (t-test / Welch, Wilcoxon / Kruskal-Wallis, χ² / Fisher). The figures print the same clustered GEE p-value as the GEE columns only when a patient-ID column is mapped, Cluster p-values by patient is on (Special outputs), the GEE source shown in summary tables is main, and — on a matched cohort whose matching weights are not all 1 — Use matching weights in matched GEE is on. Otherwise a table's GEE column and a figure can show different p-values for the same comparison: without a patient ID (or with clustering off) the figures use the eye-level tests, like the other columns of the table (and without a patient ID the GEE treats each eye as its own cluster). When all of this holds, the match is exact for two groups; with more than two, a figure's main p-value is one overall GEE test, and its “vs reference” lines come from the same model as the GEE columns, Holm-adjusted as there (marked [Holm]).

StandardEyes figures & astigmatism vector plots

Rendered natively from your data (same bins & conventions as your Excel templates — no macros needed): cumulative Snellen VA, change in CDVA lines, UDVA vs CDVA, attempted-vs-achieved SEQ with ±0.50/±1.00 D bands, SEQ accuracy, refractive astigmatism, TIA vs SIA, correction index, angle of error, plus JCRS 2025 double-angle plots in plus-cylinder format (preoperative astigmatism, SIA and the prediction error, each with its centroid). Every group is superimposed on the same chart in its own colour, before matching and for each matched pairing. The stability-over-time graph is produced when you map your follow-up visits below. Uses the column roles below (Pre/Post SEQ, VA, cylinder & axis).

EPS is vector (for journals); semi-transparent points and regions inside it are drawn as images at 1200 dpi or the resolution below, whichever is higher. Colors are RGB: convert to CMYK outside the app if the journal asks.

50 to 1200: 300 for photographs, 1200 for line art (journal requirement). PDF and EPS are vector and do not use it, except for the semi-transparent parts of an EPS.

journal: white, no frames, section bands, captions or shaded wedges; each figure's title, method notes and abbreviations go to <figure>_legend.txt beside it. annotated keeps them inside the images.

A width lays every figure out at that width, so its text keeps its point size (never below 6 pt); composites get two panels per row (one at 8.76 cm), and a combined figure taller than a 23-cm page is split into pages (_p1, _p2 …), each with its own legend file, the panel letters continuing. 8.76, 12.69 and 17.77 cm are the journal column widths.

Your file keeps one row per eye, so each visit is a separate set of columns. Add one row below per follow-up time point and pick its columns — nothing is filled in automatically; Suggest visits only proposes rows from the column names for you to check. For each visit either pick a ready SEQ column, or leave it blank and give sphere + cylinder and the app computes SEQ as sphere + cylinder/2. A visit is used only if it has a time column plus one of those. The curve joins the composite as its own extra panel — nothing is displaced. It belongs to the Full panel set; the Refractive and Cataract sets have no stability slot.

The percentage is paired — only eyes measured at both chosen visits count. Points with fewer than 3 eyes are dropped, and each visit is plotted at its median day, so the n row is the honest record of who actually returned.

The published Reinstein/JRS metrics with every group on one chart in its own colour, for any number of groups, plus JCRS-standard double-angle astigmatism plots. Nothing is split into pairs or drawn per group alone; the stat line is an omnibus test plus each group against the reference. Where a panel header prints d =, it is Cohen's d with the pooled SD, computed per eye and unweighted, whichever test (classical, GEE or weighted) gave the P value. Files are written as StandardEyes_*. (mEYEstro/AstigMATIC-format Excel tabs for external tools are still available under Optional analysis tabs.)

You will get:

Adds the “Astigmatism (JCRS 2025)” and “Astigmatism vectors” sheets and a CSV copy: centroids, total SD, magnitudes, intervals and the standard's tests for every vector and cohort, and each eye's vectors (magnitude, plus axis, x, y) for external tools.

Every astigmatism test: the centroid against zero, and between cohorts the centroid, the precision (distances to the cohort centroid) and the mean magnitude. Robust: the centroid against zero by the bootstrap projection-distance test of the WHWK functions (the journal's reference tool; 999 bootstrap centroids, P = .001 is its floor), and between cohorts 20%-trimmed tests (trimming and winsorizing by order statistics) calibrated by a bootstrap that resamples patients within each cohort. GEE: clustered Wald tests. Classic: one-sample Hotelling / Hotelling / Welch with eyes independent.

Polygon: the depth-based convex polygon as the WHWK functions build it — the convex hull of the eyes whose projection depth around the centroid reaches the depth of rank floor(0.05 n + 0.5); depths tie, so it can hold more than 95% of the eyes (the count is reported); below 10 eyes, the hull of all eyes. Normal: bivariate-normal ellipse. Both: both are drawn.

Bootstrap: as the WHWK functions build it — the convex hull of the 999 bootstrap centroids nearest the centroid by projection distance, keeping 95% of them (up to 98% for 120 or fewer resampling units); patients resampled when clustered; no normality assumption. Hotelling: the T² ellipse.

Writes a WHWK input folder inside the run's figure folder (Graphs_<prefix>_…, beside the figures): for each plotted vector (PRE, SIA, PE, and POST when plotted) a tab-delimited <vector>_vector.txt (columns <Cohort>.x, <Cohort>.y, plus-cylinder double-angle form) and <vector>_magnitude.txt, with a README, ready for the Wilcox-Holladay-Wang-Koch R functions the JCRS 2025 standard recommends (https://osf.io/xhe8u/). That tool treats eyes as independent and refuses values beyond 6 D.

What this changes. On: each group reports its total SD (√(var x + var y), population denominator, rotation-invariant), centroids are compared with the bivariate test chosen under Astigmatism tests, and the P values are Holm-adjusted within each vector across centroid, precision, magnitude and intervals, and across the comparisons with the reference. Off: the figures use two separate univariate tests on x and y, unadjusted — the app's older behaviour; the astigmatism sheet keeps the standard's tests. Every figure prints which of the two was used.

Per JCRS 2025 Part II: double-angle plots in plus-cylinder format (with-the-rule on the left) of the preoperative astigmatism, the SIA and the prediction error, each cohort's centroid, total SD, magnitude mean ± SD, median, range and RMS, the 95% depth-based convex polygon of the eyes and the bootstrap convex polygon of the centroid, built as in the WHWK functions (the paper notes astigmatism data are usually not Gaussian), the test of each centroid against zero as in the WHWK functions, the cumulative intervals ≤0.25 … ≤2.00 D, and the tests of centroid, precision and magnitude.
NOT per the standard: the normal-ellipse and Hotelling options and the semicircle plot (kept for familiarity). The robust between-cohort tests (20%-trimmed, 999 bootstrap resamples of patients — of eyes when P values are not clustered) are robust and cluster-aware but are not the exact trimmed-Hotelling variant of Part II (see the Statistical Reference).

Two eyes of one person are not independent. With this on, every figure P value — and, with Summary-table tests = auto (GEE tab, the default), every per-eye P value of the summary tables — comes from a GEE with robust standard errors clustered on the patient wherever a patient has two analyzed eyes (exchangeable working correlation; independence on a matched cohort; small-sample correction as set on the GEE tab), so a patient contributing both eyes counts once; the astigmatism tests resample or cluster patients. Leaving it off treats the eyes as independent (classical tests everywhere) and inflates significance: in simulation with no true group difference, unclustered tests fired at 15% against a nominal 5%, versus 6% clustered. Each table and figure names the test it used.

The double-angle plot doubles every meridian, so with-the-rule and against-the-rule eyes group on opposite sides instead of splitting across the horizontal — this is what JCRS 2025 Standards for analyzing astigmatic outcomes (Part II) requires, and it is what makes the vector arithmetic valid. Vectors are in plus-cylinder format whatever the cylinder form of each row: with-the-rule astigmatism (plus axis 90) on the left, against-the-rule (180) on the right. The plots show the preoperative astigmatism, the SIA (postoperative − preoperative) and the prediction error (PE = postoperative − target; the postoperative astigmatism when the target is plano), plus the postoperative astigmatism as a fourth plot when a target that is not plano is mapped. Each group gets its centroid, a 95% region of the eyes and a dashed 95% confidence region of the centroid. The normal ellipse assumes the cloud is bivariate normal; the depth-based convex polygon assumes nothing and is the safer choice for skewed data.

By default the vectors are computed from the four columns you mapped as Pre Cylinder, Pre Axis, Post Cylinder and Post Axis under Column roles (bottom of this tab), against the target refraction below (zero astigmatism when none is mapped). Nothing is guessed from column names or order — if those four roles are not mapped, no vector figure is produced and the run log says so. Map a magnitude and a plus-axis column below to use your own pre-calculated vector instead — each vector is resolved independently, and the run log reports which were supplied, which were computed, and the largest disagreement between the two. PE (prediction error = postoperative − target) and DV are one vector with opposite signs: when only one of them is supplied, the other is derived (DV = −PE).

Only set a target if you did not aim for zero astigmatism. With a target mapped (in either cylinder form), TIA becomes the intended change rather than the pre-operative astigmatism and the prediction error is postoperative − target, so the numbers will not match a target-of-zero run of the same data; when any target is not plano, the postoperative astigmatism gets a double-angle plot of its own. The run log says so explicitly whenever a target is in use.

Optional analysis tabs

Target SEQ is optional: the intended postoperative spherical equivalent of each eye (monovision, a myopic cataract target). Leave it blank when every eye was aimed at plano; when mapped, SEQ accuracy is postop SEQ minus target and the attempted correction is preop SEQ minus target.
